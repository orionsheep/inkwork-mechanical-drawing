# 核心原理：为什么这样就能"生成机械制图"

> 这份文档回答一个问题：**造这种线稿工程制图的关键是什么？**
> 结论先放这里：**关键不是在 2D 上画线，而是把真实的 3D 几何摆对，让渲染器自动"提炼"出线。**
> 线、剖视图、三视图、虚线，全是几何的**副产品**，不是手画的。

---

## 1. 整体架构：一条"3D → 图"的流水线

```
  PartDef 零件表 ─┐
  R3F 模型几何   ─┼─▶  three.js 场景（真几何体，每个零件挂一个"墨水材质"）
  MachineDef     ─┘        │
                           ▼
        ┌────────── InkRenderer 多通道渲染 ──────────┐
        │  pass0 颜色/明暗   pass1 法线+零件ID  (剖视用裁剪面)  │
        │  (三视图模式下)pass2/3 深度剥离 → 被遮挡的轮廓       │
        └───────────────────┬────────────────────────┘
                            ▼
        合成着色器 compositeFragment：从 法线/深度/零件ID 的
        **不连续处** 提炼轮廓线、折线、分界线 →
        按模式画成：铅笔线稿 / 工程图（粗实线·虚线·剖面线·点画线）
                            ▼
        叠一层 DOM/SVG：编号气泡引线、三视图投影连线、标题栏、明细表
```

代码位置（都在 `src/scene/`）：

| 文件 | 作用 |
|---|---|
| `ink.ts` | **核心**。墨水材质（每个网格一个）+ 合成着色器的 GLSL 全文 |
| `InkRenderer.tsx` | 接管 R3F 渲染循环：多通道 pass、分视口（三视图）、深度剥离 |
| `Part.tsx` | 一个零件节点：挂墨水材质、剖视裁剪、拆解位移、拾取、拖动 |
| `geometry.ts` | 几何缓存（Box/Cyl/Lathe/Extrude/SquareThread/GearShape/Coil…），法线按硬边折 |
| `explode.ts` | 分层拆解：每个零件/螺栓组有自己的时间窗 |
| `src/drawing/layout.ts` | 三视图排版 + 第一角投影相机的摆放与投影函数 |
| `src/drawing/Sheet.tsx` | 三视图上的 SVG：投影连线、圆的十字中心线、标题栏 |

## 2. 第一层关键：线是怎么"提取"出来的（轮廓算法）

渲染器不画边。它对每个像素问：

> 我的邻居，深度/法线/零件ID 和我差得多吗？差得多 → 这里是一条线。

`compositeFragment` 里的 `edgeAt()` 在 8 个方向（4 正 + 4 斜）采样：

- **深度不连续**（`dEdge`）→ 物体轮廓、前后层交界 → **粗实线 / 可见轮廓**
- **零件 ID 不连续**（`abs(s.a - id0) > 0.002`）→ **两个零件之间的分界线**（装配图里特别重要：每个零件的轮廓分得清）
- **法线不连续**（`nEdge`）→ 折角、圆角边缘 → **细一点的线（折线）**
- 边缘侧对镜头时（graze），深度变化快，阈值自动抬高，避免把斜面刷成一团黑

**这就是为什么"零件分对了"这么重要**：`<Part>` 的 `index` 会被写进 ID 通道。零件 ID 一变，两零件之间就自动有线。
所以**一组几何体只要归到一个零件里，它们内部就没有分界线；归到两个零件，零件之间就自动长出轮廓**。
"机械装配图每个零件轮廓分明"这个效果，是 `Part` 划分白送的。

> `geometry.ts` 里所有几何都过了一道 `toCreasedNormals(π/5)`：硬边保持尖锐 → 法线突变 → 有折线；
> 圆面保持平滑 → 法线渐变 → 没杂线。**光滑的圆柱不会画成一绺一绺，方块棱角又一定有线**。

## 3. 第二层关键：剖视图（全剖主视图）怎么自动正确

剖视不是"切个 2D 图"，而是**用一个裁剪平面真的把 3D 模型切掉一半，然后给"切口"涂色、打剖面线**。

- `Part.tsx` 里 `SECTION_PLANE = new Plane((0,0,-1), 100)`：法线朝 −z，即**切掉 z>0（朝镜头）那半**。
- 每个网格都有一个"带裁剪"的材质（`createInkMaterial({ clip:[SECTION_PLANE] })`），
  `InkRenderer` 在剖视时把 `SECTION_PLANE.constant` 从远处扫到 0。
- 被切开的**背面**（`!gl_FrontFacing`）在着色器里被识别为"切口/内表面"，涂上 `uCut` 色，
  并把它的 ID 也偏移 half 变成"内面 ID"——**切口轮廓因此格外清晰**。
- 合成阶段：切口像素画 **45° 细实线剖面线**（`hatchLines`），
  **相邻零件方向相反**（按零件 index 的奇偶取 45°/135°）——这就是国标"相邻零件剖面线方向相反"。

**所以剖视要正确，只有两条几何纪律**：
1. **内部结构必须真的建出来**（空心的要挖空，齿轮/流道要在，见第 5 节的"挖空"）。
2. **剖切面固定在 z=0**，所以想让谁被剖到，就把它放在关于 z=0 对称的位置（多数回转体天然满足）。

装反了会怎样：厚度方向把外壳建成了实心 → 剖开是一坨色块；内部结构没建 → 剖开是空的。
**不是"画错线"，是"几何没建对"。这正是本引擎的价值：它逼你把结构建对，图自然对。**

## 4. 第三层关键：三视图（第一角画法 + 投影关系）

`src/drawing/layout.ts` 用 4 部**正交相机**（主/俯/左/正等轴测）把同一个 3D 场景各渲一次，摆成第一角布局：

```
       主视图(front)      左视图(left)
          ────────           ────────
       俯视图(top)         正等轴测图(iso)
```

- **主视图**：相机在 +z 看向 −z（前→后看）；**左视图**：相机在 −x 看向 +x；**俯视图**：相机在 +y 向下看，
  `up` 设成 −z 让物体前方朝下（第一角里俯视图画在主视图**下方**，符合 GB/T 14692）。
- 四个视图**同一比例**（`layout.scale`），所以屏幕上三视图天然满足：
  **长对正**（主↔俯共享 x）、**高平齐**（主↔左共享 y）、**宽相等**（俯↔左通过 45° 辅助线换算 z）。
  `Sheet.tsx` 的 `ProjectionLines` 就是在悬停/选中零件时画出这些投影连线和 45° miter 线。
- 主视图带剖视（`section: true`），俯/左视图不剖。
- **虚线（不可见轮廓）**：这是最难、也最能说明"这是真算法"的一处——
  `InkRenderer` 做**深度剥离（depth peeling）**：先渲最前面一层，再渲"只在第一层背后"的第二、第三层
  （`uPass==2` 里 `gl_FragCoord.z <= front + ε` 就 discard），把剥出来的那几层的轮廓
  用虚线（`dashLen` 按像素断裂）画出来。**于是被挡住的孔、内腔轮廓自动成为细虚线**，不用人画。
- 点画线 / 圆的十字中心线：来自 `centreLines`（`[起点,终点,半径?]`），是叠在场景上、用当前调色板着色的 three.js 线条。

**三视图的关键**：一个正确的 3D 模型 + 合理的 `bounds` 包围盒 + 第一角相机摆放。剩下的投影关系、虚线、剖面线全部自动。

## 5. 第四层关键：建模纪律（几何决定一切）

因为"图"是"几何"的函数，所以真正决定成败的是**你怎么摆几何**：

1. **单位和坐标统一**。一台机器一种单位；+x 前、+y 上、地面 y=0、对称面 z=0。
   剖切面固定 z=0，坐标系一旦乱，剖视和中心线就全乱。
2. **回转体用 `Turn` 车削**：profile 是 `(半径, 轴向位置)` 闭合轮廓，**从轴心出发、一圈点描外轮廓**。
   实心件给外轮廓；**空心/薄壁一定要给"外轮廓 + 反向内轮廓"**（`tube()`/`cone()`/`dome()` 是模板）。
   `ccw()` 负责把绕向理顺，让"背面=材质内侧"这个约定成立，剖切才好看。
   **这是最常出错的地方**：只想给外表面、结果建成实心 → 剖开是一坨。
3. **折角留硬边**：用 `Box`/`Turn` 的尖角，不要在建模里倒大圆角；渲染器靠法线突变画折线，硬边才利落。
4. **看不见的不乱建，要讲的一定建**：内部结构（齿轮、阀芯、流道）不建出来，剖视里就什么都没有。
5. **缓存键唯一**：`Turn/Plate/Pipe` 按 `k` 缓存几何，同名会串味。一律加机器前缀。
6. **number↔literal**：零件 `index` ≤ 31（ID 通道精度）。

## 6. 第五层关键：让"结构"可读（拆解、讲解、引线）

- **分层拆解**：`PARTS.stage` 给每个零件一个时间窗，按装配逆序 → 拖动滑杆就是"看拆装过程"。
  `explode` 的方向要朝"真实会拿出去的方向"，图才像真的爆炸图。
- **引线气泡**：每个零件一个 `<Callout>`，`p` 放在朝镜头的表面；导出 PNG 时气泡会被径向推开并避让（`export.ts` 的 `relax`）。
- **讲解步骤**：`STEPS` 让观众"先看整体→再剖开看原理→再拆开看结构"，每步可 `focus` 特写。
- 这些是"图能讲清机械结构"的关键，和三条数据（PARTS/几何/步骤）直接对应。

## 7. 速查：三条"一定"和三条"一定不"

**一定**：
1. 一定只写**数据 + 几何**，别碰渲染器（渲染器已写好，写对几何它就出图）。
2. 一定把**要剖开讲的内部结构真的建出来**，并放在关于 z=0 对称的位置。
3. 一定**逐张看自检截图**（`check-machines --shots`），出画就调相机，别凭感觉交。

**一定不**：
1. 不混用单位、不把对称面挪离 z=0（否则剖视/中心线全错）。
2. 不把薄壁件画成实心（剖开没法看）。
3. 不让多件运动各用各的计时（要从同一相位按比例算，否则联动对不上）。
